# EP.02 · PS5 防破解：索尼到底做了什么？

2026-11-11 完整重做。保留已经确认方向的四场开头，再沿着观众的问题往下讲；不把“为什么难破解”讲成“发售前为什么不能玩”。

观众没有读过原始聊天，也不需要认识加密、数字签名、内核或虚拟机监控器。先出现要保护的东西，再解释风险、索尼的应对，以及这道防线的限度。自然语速，不再为了三分钟加速。每场先留 1.2 秒看图，讲完再留 2.2 秒消化，结尾停留 4 秒。

逐场完整口播稿以 [episode.json](episode.json) 的 `narration` 为唯一来源。字幕与逐步出现的图形使用同一份实际配音时间轴；不是提前把整页知识点摆给观众。

| 场景 | 观众的问题与画面 |
|---|---|
| 先认识 PS5 | 主机、电视、手柄；买好的游戏可以正常运行 |
| 游戏就是程序和素材 | 程序控制玩法，素材提供画面和声音；文件在自己的机器里 |
| 能玩，是否就能随便破解 | 文件在手，能否读出、修改、绕过原来的限制 |
| 索尼为了防破解做了什么 | 要保护文件、解密能力和检查程序 |
| 先防直接读懂程序 | 文件在手不等于内容可读；先讲打乱与还原，再给出“加密”这个名字 |
| 主机能用钥匙，不等于交出钥匙 | 普通应用发起受控请求，敏感解密能力在隔离边界后面 |
| 能执行代码，不等于能随便读取 | 部分代码允许处理器执行，不允许任意读取；秘方类比明确不是所有内存都不可读 |
| 读懂并改好了，机器就肯运行吗 | 已签名程序：原版通过，改版验签失败 |
| 为什么不能自己补一个签名 | 内容与签名绑定；可信重签需要秘密签名钥匙，不与解密钥匙混为一谈 |
| 那就改掉检查程序 | 从改游戏转到改系统；提出“谁保护检查程序” |
| 游戏先被限制在自己的范围 | 用一间受限的房说明沙箱，先讲限制，再讲名称 |
| 谁来管理这些权限 | 内核管理程序、内存和权限；控制一间房不等于管理整栋楼 |
| 内核上面，还有谁来管 | 先讲约束内核的作用，再出现 Hypervisor；只是简化权限图 |
| 为什么需要一串不同的突破 | 多个边界、多个条件；局部漏洞不自动等于整机失守 |
| 防线不是绝对不会被突破 | Byepervisor 公开研究，附适用版本与前提条件，不给利用步骤 |
| 索尼也在堵住已知缺口 | 修补可能切断原来的漏洞链；不声称更新能保证永久安全 |
| 安全突破和电脑兼容，是两件事 | 只顺带说明“导出”不自动等于“PC 可玩”，不偏离防破解主线 |
| 能玩，不等于能随意控制 | 回到保护文件、防止修改、防止越权三个目的 |
