# CA 电子签章 · 事实核对笔记

## 1. 法律底线

- 《中华人民共和国电子签名法》（2019 修正）第十四条：**可靠的电子签名与手写签名或者盖章具有同等的法律效力。**
- 第十三条：同时符合以下四项，视为可靠电子签名：
  1. 签名制作数据用于签名时，属于签名人专有；
  2. 签署时，签名制作数据仅由签名人控制；
  3. 签署后，对签名的任何改动能够被发现；
  4. 签署后，对数据电文内容和形式的任何改动能够被发现。
- 第三条：涉及婚姻、收养、继承等人身关系的文书，涉及停止供水、供热、供气等公用事业服务的文书，不适用本法；法律、行政法规另有规定的从其规定。
- 第十六条：需要第三方认证的，由依法设立的电子认证服务提供者提供认证服务。国内 CA 需取得电子认证服务许可。

**易错点**：法律认的是“可靠的电子签名”，不是红章图片。把印章图片贴进 PDF、扫描件、打印件，都不满足第十三条。

## 2. 密码学骨架

- **哈希**：SHA-256（国密对应 SM3）。输入任意长度，输出固定长度摘要；改一个字节，摘要雪崩式变化；不可逆。
- **非对称密钥**：私钥签名，公钥验签。私钥泄露 = 身份被冒用；私钥丢失 = 无法签署。
- **签名流程**：对 PDF 的 `/ByteRange` 计算摘要 → 用私钥对摘要做签名运算 → 把签名值、证书链、可选时间戳写入 PDF 签名域。
- **验签流程**：按 `/ByteRange` 重算摘要 → 用证书公钥验证签名值 → 比对摘要 → 验证证书链、有效期、用途、吊销状态、时间戳。
- **PDF 结构**：签名值在 `/Contents`，覆盖范围由 `/ByteRange` 指定；签名后追加内容属于增量更新，原签名仍覆盖旧字节，但阅读器会提示“签名后文档被修改”。
- **多签名**：PDF 支持多人会签；后一个签名通常覆盖前面所有字节。验证时要逐个签名看，不能只看最后一个章。
- **PAdES**：ETSI EN 319 142 系列，PDF 高级电子签名；B-B / B-T / B-LT / B-LTA 逐级增强。LTV 需要把证书链、CRL/OCSP、时间戳等验证材料存进 DSS。
- **时间戳**：RFC 3161，由 TSA 签发；证明“某时刻该数据已存在”。证书过期后，靠可信时间戳证明签名当时的有效性。
- **吊销**：CRL 列表或 OCSP 在线查询；证书可能因私钥泄露、主体信息变更等被吊销。
- **国密**：SM2 签名、SM3 摘要；PDF 中常见 OID `1.2.156.10197.1.501`（sm2sign-with-sm3）。Adobe 默认信任库和验证链对国密支持有限，常需专用阅读器或验签平台。

## 3. CA 与证书链

- **CA**：Certificate Authority，依法设立的电子认证服务机构；**RA**：注册审核机构，负责受理和实名核验。
- 典型签发流程：提交资料 → 实名审核（营业执照、法人身份、授权书、人脸识别等）→ 生成/提交密钥对与 CSR → CA 签发 X.509 证书 → 下发到 UKey/云端 → 可查询、可吊销。
- **证书字段**：版本、序列号、签名算法、颁发者、有效期、主体、公钥、扩展项（Key Usage、Extended Key Usage、CRL 分发点、OCSP 地址等）。
- **证书链**：根 CA（自签名，预置在信任库）→ 中间 CA → 用户证书。验证时逐级向上，直到受信根。
- **信任库差异**：Adobe 有 AATL（Adobe Approved Trust List）；操作系统/浏览器也有自己的根证书库。国内 CA 的根证书未必在 Adobe 默认列表里，所以会出现“签名有效性未知”，这不等于签名一定无效。
- **证书用途**：文档签名证书通常要求 `nonRepudiation`/`digitalSignature` 等 Key Usage；时间戳证书要求 `id-kp-timeStamping`。

## 4. 验签看什么

1. **完整性**：签名覆盖的字节是否被改过；PDF 是否有签名后的增量修改。
2. **签名者身份**：证书主体是谁；CA 是谁；证书链是否完整、是否受信。
3. **证书状态**：有效期、是否吊销（CRL/OCSP）、Key Usage 是否匹配。
4. **时间**：签名时间戳是否有效；TSA 证书是否受信；长期验证材料是否齐全。
5. **签名策略**：文档是否有认证签名（DocMDP）、是否允许表单填写/注释等后续修改。

**Adobe 常见状态**：
- 绿色对勾：签名有效，文档未被修改（前提是证书在信任列表内）。
- 黄色警告：签名有效性未知（证书不受信任/链不完整）、证书过期、时间戳无法验证、文档签名后被修改。
- 红色/无效：签名值不匹配、文档被篡改、签名损坏。

## 5. 常见坑与误区

- **红章图片 ≠ 电子签章**：图片可复制、可 PS；没有证书、没有签名值、没有日志。
- **截图/扫描/打印 = 图片**：脱离原始 PDF 后，密码学签名无法随纸传递；打印件的红章没有数字签名意义。但打印件仍可能作为其他证据使用，关键是能否提供原始电子文件、CA 证书、时间戳和签署日志。
- **改一个字就失效**：哈希雪崩；哪怕只改日期、空格、标点，验签都会失败。
- **证书过期 ≠ 签名当时无效**：有可信时间戳时，可证明签署发生在证书有效期内；没有时间戳则难以证明。
- **自签名证书 ≠ CA 证书**：自己给自己签的证书不在公共信任链里，不能证明身份。
- **“签名有效性未知” ≠ 假签名**：可能只是阅读器不认识国内 CA 根证书；应换验签平台或导入根证书后再判断。
- **国密 PDF 兼容性**：Adobe 对 SM2/SM3 支持有限；国内电子发票、电子合同常用 OFD 或专用验签工具。
- **云签平台托管密钥**：方便，但私钥由平台控制；要关注平台的资质、审计、授权与责任边界。
- **时间戳不是签名**：时间戳证明“存在时间”，签名证明“谁签的、内容没改”；两者配合才完整。

## 5.5 图片、打印件与法院验证

- 图片、截图、打印件本身不是可靠的电子签名，不能单独证明签名有效；但它可以是证据线索。
- 打印件仍可能作为书证或其他证据使用；关键看能否提供原始电子文件、CA 证书、时间戳、签署日志。
- 法院可以核对原始 PDF 的签名面板、证书链、时间戳、签署日志，必要时委托司法鉴定或第三方验签。
- 法律依据：《电子签名法》第十三条、第十四条；最高人民法院《关于民事诉讼证据的若干规定》对电子数据的审查判断。
- 表述纪律：不要说“图片完全没有法律效力”；准确说法是“图片本身不构成可靠的电子签名，但可以作为证据线索”。

## 6. 典型场景

- 电子劳动合同、电子采购合同、房屋租赁合同；
- 电子发票（PDF/OFD）、银行电子回单；
- 招投标文件、政府采购；
- 政务审批、电子证照；
- 多人会签、骑缝章（多页合同每页显示印章局部，技术上仍由数字签名保护整份文件）。
